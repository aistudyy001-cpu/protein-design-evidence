# 蛋白质设计证据工作流

本项目围绕 AI 设计纳米抗体（VHH）与迷你结合蛋白（minibinder），建设可追溯的计算评价和候选审计流程。

研究关注的问题是：生成的候选具有较高模型分数时，能否明确解释其输入条件、结合姿态、折叠形状及失败原因，并在后续实验中验证？

## 研究背景与范围

完整研究流程曾开展 NK2R 纳米抗体候选设计，并评估长江杯不同靶点的设计路线。NK2R 任务涉及无天然配体条件下的受体激动作用，计算结构分数不能替代功能实验。

公开仓库提取了既有 ProteinDesignPipeline 中三个独立审计模块及既有指标测试，并提供可运行的合成坐标示例。它用于展示真实项目的目标、部分代码和研究方法，不包含完整模型执行系统。

## 可直接运行的功能

- 文件和对象 SHA256、JSON 输入输出。
- 按靶链与 binder 链分别汇总跨链 PAE。
- 将靶点自身变形、binder 相对姿态与 binder 自身形状分开评价。
- 使用合成数据检查“自身形状不变，但相对结合姿态改变”的情况。

运行方法见 [英文 README](README.md)。示例不需要 GPU、模型权重或 API；所用坐标与分数均为合成数据。

## 研究原则

候选身份、输入构建体、MSA、模板和评价条件需要明确记录；不同条件不能简单合并成一个通过率。高置信度模型仍需检查几何和实际实验背景。实验活性与计算指标分开报告，失败结果保留用于否证和改进。

AI 助手用于资料整理、协议草拟、代码编写、排错和团队沟通，结论仍须依据可审查的证据。项目的科研序列、未公开数据、模型权重、服务器配置和凭据均未包含在此公开版本中。
